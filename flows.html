How people move through AD as a Service

Three agents, three places. Salesy talks to people who don't have an account yet. Configgy sets up and changes an account, and only admins can reach it. ADy does the actual data work for everyone in the account. Each flow below has a button that opens the prototype at that exact point.

Where things live

SalesThe site · SalesyWhat you see before you have an account: what AD can do, how it works, why it's safe, and how to start. Salesy is the chat box on the home page. This is also where you register and set up your account.
PortalSign inOne sign-in for everyone. Who you are decides what you see: an admin gets both the AD and Configure sections, a regular user gets AD only, Alida staff see every account and pick one to work in.
ConfigureConfiggy and the Configure pagesAdmins only: Setup, Domains, Sandboxes, People, Approvals, Usage, Audit log. Do it yourself on the page, or ask Configgy in the assistant panel and approve what it drafts.
ADADyWhere the work happens: Data, Produce, Explore, Generate, Work orders. You tell ADy what you need in the assistant panel and it runs the job. ADy cannot change your setup; if you ask for that, it passes the request to Configgy for an admin to approve.

Four words to agree on

WordWho uses itWhat it means
Sales OrderSalesyWhat you agreed to when you signed up: which work solution, how much you're willing to spend, who your users are, where it runs. It is final once you pay.
Config OrderConfiggyAny setup or change to an account, whoever asked for it: the sales order, an admin on the dashboard, an admin talking to Configgy, or a user asking ADy. An admin either does it directly or approves it.
JobConfiggyOne script that runs as part of a config order: set up the environment, configure the service, start AD, verify.
Work OrderADyA piece of data work: bring data in, produce, explore, generate. Never a setup change.

First they register: name, organisation, email, password. That makes them the account's admin. Then six short steps with Salesy alongside:

  1. Pick a work solution.
  2. Confirm the organisation and admin.
  3. Set a monthly spending limit.
  4. List the people who will use AD, and say which of them are admins.

  6. Review the sales order, confirm, pay.

Setting up and changing an account · Configgy

8
The environment gets builtConfigure

Nobody has to do anything here; the new admin just watches it happen:

  1. The sales order is checked.
  2. The Azure environment is set up.
  3. The service is configured: domains, the first sandbox, the people.
  4. AD is started and verified.

When it's done, the admin opens the account and lands on the overview, with a short getting-started list: environment provisioned, invite your team, run your first job.

An admin changes something by handConfigure

Go to the right Configure page (Domains, Sandboxes, People, Setup), make the change, press Add or Save. It is checked and applied right away, and written to the audit log as a config order.

This is the safety net. If Configgy got something nearly right, the admin fixes the last bit here instead of asking the agent again. Nobody ever goes into the Azure portal.

The rules behind it

  • Sales hands over to Configure once, when the account is paid for. After that nobody goes back to Sales.
  • Admins move freely between Configure and AD. Users only have AD, and can only ask for setup changes.
  • The agents stay in their lane. Salesy can't configure anything. Configgy can't do data work and can't approve its own orders. ADy can't change the setup.
  • Every setup change is a config order, no matter who asked. One way to apply, one audit log.
  • The dashboard is always there as the manual way. The agent is a convenience, not the only path.

What we need to decide

  1. Are these the four words: Sales Order, Config Order, Job, Work Order?
  2. Which changes can an admin apply directly on the dashboard, and which must be reviewed first? Proposal: anything done by hand applies at once; anything an agent drafts waits for approval.
  3. Do clients set up their account through the steps, through Salesy, or both? Proposal: both, with the steps as the visible path and Salesy helping fill them in.
  4. When a user asks ADy for a setup change, should ADy raise the request itself, or tell them to go to their admin?
  5. Models, recovery and closing accounts: define the smallest version now, or leave them open?
  6. Which of the flows above do we build first?
